0. Cómo usar este documento  
La idea central del proyecto es una persecución entre un misil (perseguidor) y un 
avión (evasor) . Cada uno es un sistema dinámico: evoluciona según ecuaciones 
difer enciales, lo que nos permite estudiar estabilidad y estrategias de control. La 
simulación produce, en cada instante de tiempo, la posición y velocidad de ambos 
objetos; esos datos son los que alimentan los tres gráficos . 
Para que todos puedan arrancar hoy mismo:  
1. El Grupo 1  (nosotros) publica este documento y el archivo types  + mockResult  
de la sección 5 (los tipos del contrato de datos y un resultado de ejemplo).  
2. Los Grupos 3, 4, 5 y 6  construyen contra ese mockResult  desde el primer 
minuto, sin esperar al backend.  

3. El Grupo 2  implementa la función simulate(config)  respetando exactamente 
la forma de SimulationResult . El día de la integración, se reemplaza el mock  
por la función real y todo encaja.  
El contrato de datos (sección 5) es la pieza que sostiene todo. Si todos respetan esa 
forma, los pedazos encajan sin renegociar nada.  
 
1. Visión del producto final  
Una aplicación de una sola página con dos pestañas : 
• Pestaña “Simulación”  — el corazón visual. A la izquierda, un panel de 
controles para cargar las condiciones iniciales y elegir el escenario; a la 
derecha, los tres gráficos  dispuestos juntos. Una barra de reproducción 
única  (play / pausa / velocidad / barra de desplazamiento temporal) controla 
los tres gráficos a la vez : el avión y el misil se mueven en la grilla 2D, los 
mismos objetos se mueven en 3D, y un cursor recorre la curva de distancia. 
Todo sincronizado en el mismo instante de simulación.  
• Pestaña “Fundamentos teóricos ” — las fórmulas en LaTeX, la deducción paso 
a paso de las ecuaciones y la explicación de por qué el sistema es no lineal, 
cómo se linealiza y qué dice la estabilidad.  
El profesor disfruta lo que se mueve, así que la apuesta principal es la sincronización 
de los tres gráficos bajo un solo reproductor  (sección 7.4). Esa es la función que 
hace que todo se vea vivo.  
Flujo de uso típico:  El usuario carga posición/velocidad iniciales del avión y del misil, 
elige la ley de guiado del misil (persecución pura o nav egación proporcional) y la 
maniobra de evasión del avión, presiona “Simular”, y luego reproduce la animación. La 
app muestra si hubo intercepción, en qué momento y cuál fue la distancia mínima 
alcanzada.  
 
2. Stack tecnológico y dependencias  
El proyecto se  construye como una aplicación web React, con todo corriendo en el 
navegador  y sin un servidor aparte. Motivo de la decisión: con un plazo al jueves y 
seis grupos, un esquema cliente/servidor agregaría una capa de red que hay que 
coordinar y que no aporta nada para esta demo. El cálculo numérico de esta 
simulación corre sin problema en el navegador, así que no hace falta backend remoto: 
el “backend lógico” del Grupo 2 es simplemente un módulo de funciones en TypeScript 
que se ejecuta del lado del cliente.

3.4 Maniobras de evasión del av ión (cómo se calcula la aceleración del avión)  
Variar la maniobra del avión da escenarios distintos y vistosos. Proponemos un menú 
seleccionable:

• Viraje constante  (círculo):  de magnitud fija, perpendicular a . Da una

• Serpenteo / weave  (senoidal): aceleración lateral

maniobra).  
3.5 Integración numérica (cómo avanza el tiempo)  
Las ecuaciones diferenciale s se resuelven numéricamente paso a paso.

precisión y simplicidad; ofrecemos también Euler como opción didáctica para mostrar

type Vec3 = [number, number, number]; 
 
// Helpers vectoriale s (o usar mathjs)  
const sub = (a: Vec3, b: Vec3): Vec3 => [a[0]-b[0], a[1]-b[1], a[2]-
b[2]]; 
const add = (a: Vec3, b: Vec3): Vec3 => [a[0]+b[0], a[1]+b[1], 
a[2]+b[2]]; 
const scale = (a: Vec3, s: number): Vec3 => [a[0]*s, a[1]*s, a[2]*s]; 
const dot = (a: Vec3, b: Vec3): number => a[0]*b[0] + a[1]*b[1] + 
a[2]*b[2]; 
const cross = (a: Vec3, b: Vec3): Vec3 => [ 
  a[1]*b[2] - a[2]*b[1], 
  a[2]*b[0] - a[0]*b[2], 
  a[0]*b[1] - a[1]*b[0], 
]; 
const norm = (a: Vec3): number => Math.sqrt(dot(a, a)); 
 
// Aceleración del misil según navegación proporcional (PN)  
function  missileAccelPN (rA: Vec3, vA: Vec3, rM: Vec3, vM: Vec3, N: 
number): Vec3 {  
  const rRel = sub(rA, rM); 
  const vRel = sub(vA, vM); 
  const R2 = dot(rRel, rRel); 
  const omegaLOS = scale(cross(rRel, vRel), 1 / R2); // ω_LOS = (r×v)/R²  
  return scale(cross(omegaLOS , vM), N);               // a_M = N (ω_LOS × 
v_M)  
} 
3.6 Estabilidad y clasificación (lineal / no lineal / homogéneo)  
Esta sección conecta el proyecto con lo visto en clase y  es el material principal de la 
pestaña teórica.  
• El sistema completo es NO LINEAL.  La normalización , la división por 
 y los productos vectoriales hacen que  no sea una función lineal del 
estado. (Equivalentemente, en la forma por ángulos aparecen  y .) 


• Linealización.  Si linealizamos las pequeñas desviaciones respecto del 
triángulo de colisión nominal  (la geometría en que ambos van directo al 
impacto), las perturbaciones del estado obedecen un sistema lineal  
. 
• Sistema HOMOGÉNEO.  Si el avión no maniobr a (no hay forzado externo), la 
dinámica del error de puntería (“miss distance”) es un sistema lineal 
homogéneo  , y su respuesta libre es la que decide si el misil 
intercepta. Cuando el avión sí maniobra, aparece un término de forzado y el 
sistema pasa a s er no homogéneo . 
• Resultado clásico de estabilidad de PN.  La navegación proporcional lleva la 
velocidad de rotación de la LOS a cero (curso de colisión). Para que la 
aceleración comandada se mantenga acotada  hasta el momento de la 
intercepción (en lugar de dispararse al infinito), se necesita ; por eso en 
la práctica se elige  a . Este es un resultado conocido y citable, y sirve 
para discutir estabilidad numéricamente: la UI puede dejar variar  y mostrar 
cómo cambia la curva de distancia y el perfil de aceleración.  
Tip para la demo:  una función opcional analyzeStability(config)  puede 
devolver, para el caso linealizado de coeficientes constantes, los autovalores 
de  y una etiqueta (“estable” / “ inestable”). Es un puente directo entre la 
materia (sistemas homogéneos y autovalores) y lo que se ve en pantalla.

Reglas de oro de la comunicación:  
1. Una sola dirección para los datos pesados.  El backend produce 
SimulationResult ; los gráficos solo lo consumen. Los gráficos no calculan 
física: si un gráfico necesit a un número (distancia, velocidad de aproximación), 
ese número ya viene calculado en el resultado.  
2. La UI es la dueña del tiempo.  Mantiene currentFrame  (índice del instante 
actual) y se lo pasa a los tres gráficos. Así los tres muestran siempre el mismo 
instante. Esto es lo que produce la sincronización (sección 7.4).  
3. Los gráficos son componentes independientes.  Cada uno recibe result  y 
currentFrame  como props y no sabe nada de los otros dos. Se pueden 
desarrollar y probar por separado contra el mockResult .

5.1 Entrada: SimulationConfig  
type Vec3 = [number, number, number]; // [x, y, z] en metros (z = 0 para 
2D) 
 
type GuidanceLaw = "pure_pursuit"  | "proportional_nav" ; 
type ManeuverType = "straight"  | "constant_turn"  | "weave" | 
"reactive_evade" ; 
type Integrator = "euler" | "rk4"; 
 
interface  SimulationConfig {  
  aircraft : { 
    position : Vec3;       // posición inicial (m)  
    velocity : Vec3;       // velocidad inicial (m/s)  
    maneuver : ManeuverType ; 
    maxAccel : number;     // aceleración lateral máxima (m/s²)  
    maneuverParams ?: {    // opcional, según la maniobra  
      turnRate ?: number;  // rad/s, para constant_turn  
      weaveAmp ?: number;  // m/s², amplitud del serpenteo  
      weaveFreq ?: number; // rad/s, frecuencia del serpenteo  
    }; 
  }; 
  missile: { 
    position : Vec3; 
    velocity : Vec3; 
    guidanceLaw : GuidanceLaw ; 
    navConstant : number;  // N (solo se usa con proportional_nav), típico 
3–5 
    maxAccel : number;     // m/s²  
  }; 
  simulation : { 
    dt: number;           // paso de tiempo (s), p. ej. 0.02  
    maxTime: number;      // tiempo máximo de simulación (s)  
    hitRadius : number;    // distancia de intercepción (m)  
    integrator : Integrator ; 
  }; 
} 
5.2 Salida: SimulationResult  
Toda la app gira en torno a este objeto.  Cada arreglo está indexado por instante: 
time[i] , aircraft.position[i] , missile.position[i] , distance[i]  corresponden 
todos al mismo paso i. Esto hace trivial la sincronización: el currentFrame  de la UI es 
simplemente ese índice i. 

interface  SimulationResult {  
  time: number[];                 // [t0, t1, ...] en segundos  
 
  aircraft : { 
    position: Vec3[];             // posición en cada instante  
    velocity : Vec3[]; 
    speed: number[];              // |v| en cada instante  
  }; 
 
  missile: { 
    position : Vec3[]; 
    velocity : Vec3[]; 
    speed: number[]; 
    accelCommand : number[];       // magnitud de la aceleración comandada 
(m/s²)  
  }; 
 
  // Cantidades de la geometría del encuentro (alimentan al Gráfico 3)  
  distance : number[];             // R = |r_A − r_M| en cada instante  
  closingVelocity : number[];      // V_c en cada instante  
  losAngle : number[];             // ángulo de la línea de visión (rad), 
útil en 2D  
 
  // Desenlace  
  outcome: { 
    intercepted : boolean; 
    interceptTime : number | null; // s, o null si no hubo intercepción  
    minDistance : number;          // distancia mínima alcanzada (m)  
    minDistanceTime : number;      // instante de la distancia mínima (s)  
  }; 
 
  metadata : { 
    config: SimulationConfig ;     // la config con que se generó  
    steps: number;                // cantidad de ins tantes (= 
time.length)  
    integrator : Integrator ; 
  }; 
}

7.4 Sincronización: el reproductor único (la función clave)  
Esto es lo que hace que todo “esté vivo” y es la pieza que recomendamos cuidar más.  
• La UI (Grupo 3) mantiene un solo  estado currentFrame  (un entero de 0 a 
result.steps − 1 ). 
• La PlaybackBar  lo incrementa con requestAnimationFrame , a un ritmo 
modulado por la velocidad elegida (×0.5, ×1, ×2). Play arranca el bucle, Pausa lo 
detiene, y la barra de desplazamiento lo fija manualmente.  
• Ese mismo  currentFrame  se pasa como prop a los tres  gráficos. Como los tres 
arreglos están alineados por índice (sección 5.2), los tres muestran 
exactamente el mismo instante: el avión y el misil aparecen en la misma 
posición en 2D y en 3D, y el cursor de distancia marca ese mismo tiempo. Cero 
lógica de si ncronización adicional : alcanza con compartir un número.

const [currentFrame , setCurrentFrame] = useState (0); 
const [playing , setPlaying] = useState (false); 
const [speed, setSpeed] = useState (1); 
 
useEffect (() => { 
  if (!playing) return; 
  let raf: number; 
  let last = performance .now(); 
  const tick = (now: number) => { 
    const dtReal = (now - last) / 1000; 
    last = now; 
    setCurrentFrame ((f) => { 
      const next = f + speed * dtReal / 
result.metadata .config.simulation .dt; 
      return Math.min(Math.floor(next), result.steps - 1); 
    }); 
    raf = requestAnimationFrame (tick); 
  }; 
  raf = requestAnimationFrame (tick); 
  return () => cancelAnimationFrame (raf); 
}, [playing , speed, result]) ;

10. Glosario  
• LOS (Line of Sight, línea de visión):  recta imaginaria que une al misil con el 
avión. Su rotación es la clave del guiado.  
• Rango ( ): distancia entre ambos objetos. Es la varia ble del Gráfico 3.  
• Velocidad de aproximación ( ): cuán rápido se acortan; positiva si se 
acercan.  
• Navegación proporcional (PN):  ley de guiado que acelera el misil 
proporcionalmente a la rotación de la LOS; constante . 
• Persecución pura:  el misil apunta siempre a la posición actual del avión.  
• RK4:  método de Runge –Kutta de 4º orden para integrar las ecuaciones 
diferenciales paso a paso.  
• Sistema homogéneo:  , sin término de forzado; aquí, la dinámica del 
error cuando el avión no maniobra.  


• currentFrame:  índice del instante de simulación que se está mostrando; el 
número que sincroniza los tres gráficos.
